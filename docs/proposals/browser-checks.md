# Installed workspace and actual capture checks

5 November 2026. The owner's standing approval authorizes this concrete packet:
one public Ubuntu CI job, at most 20 minutes per changed candidate. Only
disposable authored data and task-owned runner storage are used. No account,
model call, paid plan, production recording or Chrome store submission.

`tests/browser.mjs` has two installed-extension journeys: desktop and plain
narrow Chromium. A genuine chooser imports a versioned two-step workflow;
edits/save/reload exercise real IndexedDB. Actual JSON and Markdown downloads
retain the edits without an ephemeral replay value. A malformed chooser file
cannot replace current work. Confirmed deletion survives reload. Request and
page-error guards apply; no fake extension APIs are injected into this workspace.

These two journeys passed in attempt 5 and are closed. The current workflow
executes capture-only after verifying the immutable accepted receipt SHA and
byte/mode equality for all twelve extension inputs. Changed product inputs
cannot borrow that old acceptance. The earlier attempts remain separate.

`tests/capture.browser.mjs` attempts one additional **actual** headed Chromium
journey under Xvfb. The operating system's xdotool presses the extension's
declared Alt+Shift+R action shortcut; the actual popup's Start button obtains
Chrome's activeTab/tabCapture grant. No permission forging, worker-private hook,
mock stream or alternate capture API substitutes for this path. Record an owned
loopback page, stop, observe/play/download the actual saved WebM and task steps,
then explicitly bind the original tab and approve the recorded click/field.
If the browser action cannot be operated, preserve that failure and its exact
stage; never relabel the two workspace journeys as capture acceptance.

The genuine action popup may be a Chrome `other` target, omitted from Playwright's
page inventory. The capture-only driver may focus its own authored fixture window
and control an exact-URL observed popup using the documented CDP Target bridge:
DOM readiness/warning/bounds reads and trusted Input press/release clicks only.
It never evaluates Chrome permission/start APIs, sets a Runtime userGesture flag
or invokes private application state. The OS shortcut remains the entry point.
Unobserved popups remain failures with bounded target/context diagnostics.

The current external runner installs pinned Playwright 1.64.1/Chromium and xdotool
only inside this disposable CI scope. Its version/integrity was read before
selection; earlier 1.58.2 launch failures remain preserved in the owning results.
Short private `/tmp/tl-*` storage and prelaunch socket-path budgets retain
isolation while fitting Chromium's Unix socket limit.
`scripts/browser-ci.py` caps each command's time and output, retains compressed
raw stdout/stderr with hashes, records all source bytes/modes before and after,
checks reaped process groups and removes only its owned scratch/generated files.
No local environment is installed: Storage Guard measured 20.0 GiB free versus
34.0 required. Earlier 31 local Node cases are closed and are not rerun here.

Tooling follows the official [Playwright extension guide](https://playwright.dev/docs/chrome-extensions)
and Chrome's [action command](https://developer.chrome.com/docs/extensions/reference/api/commands)
and [capture guidance](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture).
Linux/Chromium fixture acceptance cannot establish native Mac privacy UI,
real-user device behavior, other sites, store distribution or universal replay.
The QA-only workflow is retired after its terminal receipt; failures are immutable.
